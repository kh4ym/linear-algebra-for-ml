# Part 3 — Systems, orthogonality, least squares

**Through-line.** Part 2 taught that a matrix is a map. Part 3 asks the reverse question — *given the output, what was the input?* — and discovers that when no exact input exists, the best answer is a **shadow**. The part opens with Ax = b seen two ways (lines meeting ↔ columns combining), takes an optional detour through elimination, then builds projection onto a line and a plane, straightens bases with Gram–Schmidt, and lands on the first capstone: **fitting a line is dropping a perpendicular** (least squares, with the sample-space flip made explicit). Matrix-form regression (normal equations, pseudo-inverse for tall X, minimum-norm for wide X, a first look at conditioning) and the Gram matrix (all pairwise dot products — the object behind attention scores, kernels and covariance) close the part.

**Order (ids final).** p3-01-systems-row-column → p3-02-elimination [extension] → p3-03-projections → p3-04-orthonormal-gram-schmidt → p3-05-least-squares ★ → p3-06-regression-matrix-form → p3-07-gram-matrix.

**Shared numbers (so every lesson in the part draws the same objects).** The 2×2 system of p3-01 is A = [[2,1],[1,3]], b = [4;7], solution x = [1;2]. The projection pair of p3-03 and p3-04 is a = [3;1] (yellow) and w = [1;2] (purple). The least-squares data of p3-05 is the three points (1,1), (2,2), (3,2) with X = [[1,1],[1,2],[1,3]], y = [1;2;2], ŵ = [0.67;0.5]. The 3D plane of p3-03/p3-05 is spanned by a₁ = [1;0;1] and a₂ = [0;1;1] with b = [1;2;6], projection p = [2;3;5]. Colors follow the plan's contract: column 1 / first spanning vector green (`c-i`), column 2 red (`c-j`), third blue (`c-k`), v yellow, w purple, b orange, answers gold, projections magenta with dashed gray residuals, subspaces teal, null space magenta.

## p3-01-systems-row-column — Ax = b: row picture vs column picture
**Part** 3 · **Tags** core · **Dims** both · **Minutes** ~10 · **Prereqs** p2-02-matrix-vector, p2-07-inverse-solving, p2-08-rank-column-null
**Goal.** Given a 2×2 or 3×3 system, the learner can draw both pictures (lines/planes meeting; columns combining to reach b) and read off from either whether there is one solution, none, or infinitely many.
**Badge.** drawnIn: 2D and 3D · realSize: a linear layer with 4096 unknowns has 4096 "planes" in ℝ⁴⁰⁹⁶ · transfers: each equation is still one flat sheet, each unknown still weights one column, and the three outcomes (one / none / many) are the only ones in any dimension.
**Can't show.**
- Four or more equations as planes (only three planes fit in a 3D picture).
- Hyperplanes: in ℝⁿ an equation is an (n−1)-dimensional flat sheet, which has no picture past n = 3.
**Terms.** system of linear equations — several equations sharing the same unknowns, written as one matrix equation Ax = b; row picture — each equation drawn as a line (plane) whose points satisfy it; column picture — b drawn as a weighted sum of the columns of A; consistent — a system that has at least one solution; solution set — all x with Ax = b: a point, a line, a plane, or nothing.
**State.** `s.A` (2×2 or 3×3 matrix), `s.b` (target vector, orange), `s.x` (current candidate solution, yellow), `s.view` ('2d'|'3d'), `s.cam`, `s.mix` (0 = row picture, 1 = column picture, animates the split), `s.weights` ([x₁,x₂] sliders for the column recipe), `s.case` ('unique'|'none'|'many'), `s.showSolutionSet` (bool).
**Steps.**
### 1. Two equations, two unknowns · 3 s · flags: (none)
Narration: Here are two equations sharing two unknowns: 2x + y = 4 and x + 3y = 7. Stacked, they are one matrix equation <b>Ax = b</b>: the rows of <b>A</b> hold the coefficients, the orange <span class="c-b">b</span> holds the right-hand sides. Same facts, written once.
Canvas: 2D grid (g.grid identity, g.axes). Math panel only; the two equations slide (t 0→0.5) into the bracket form, coefficients landing in A row by row, 4 and 7 landing in the orange b bracket. Nothing else drawn yet.
Math panel: `2x + y = 4`, `x + 3y = 7` → `[[2,1],[1,3]] [x;y] = [4;7]` (rows highlighted as they fill; b in c-b).
### 2. The row picture: each equation is a line · 4 s · flags: (none)
Narration: Read <b>A</b> by <i>rows</i>. Every point (x, y) with 2x + y = 4 lies on one straight line; every point with x + 3y = 7 lies on another. A solution must satisfy both, so it must sit on both lines: the one place they cross.
Canvas: Line 1 draws itself (t 0→0.4) as a gray-white polyline through (0,4) and (2,0), labeled "row 1"; line 2 (t 0.4→0.8) through (−2,3) and (7,0) labeled "row 2". At t 0.8→1 a gold g.point pulses at (1,2) with g.label "x = [1; 2]".
Math panel: row 1 of A and b₁ underlined in sync with line 1; then row 2.
### 3. The column picture: reach b with the columns · 4.5 s · flags: (none)
Narration: Now read <b>A</b> by <i>columns</i>. Column 1, <span class="c-i">[2; 1]</span>, is where î lands; column 2, <span class="c-j">[1; 3]</span>, is where ĵ lands. Ax = b asks: how much of each column, tip to tail, reaches <span class="c-b">b</span>? One of the first and two of the second.
Canvas: Lines fade to 25 % alpha. g.vector origin→[2,1] green labeled a₁, origin→[1,3] red labeled a₂, g.vector origin→[4,7] orange labeled b. t 0.3→1: one green copy stays, then two red copies stack tip-to-tail from [2,1] → [3,4] → [4,7]; a gold ring pulses on b's tip when reached. g.label "1·a₁ + 2·a₂".
Math panel: `1·[2;1] + 2·[1;3] = [4;7]` with colored columns; weights 1 and 2 in gold.
### 4. Same answer, two pictures · 3 s · flags: interactive
Narration: The crossing point of the lines is [1; 2]. The weights on the columns are 1 and 2. They are the <i>same numbers</i>, because both pictures are the same equation. Drag <span class="c-b">b</span>: the crossing moves and the recipe changes together.
Canvas: Split canvas (s.mix animates 0→1 then holds at 0.5): left half row picture, right half column picture, both live from s.A and s.b. g.handle('b') on b's tip (right) moves b; lines on the left re-draw (line i is {p : rowᵢ·p = bᵢ}); the gold crossing and the gold weights update every frame.
Math panel: live `x = A⁻¹b = [x₁; x₂]` with LA.fmt.
### 5. No solution: parallel lines, b off the column line · 4 s · flags: misconception
Narration: "If there is no solution I made a mistake." ✕ — some systems simply have none. Take <b>A</b> = [[1,2],[2,4]]: the rows give <i>parallel</i> lines that never meet, and the columns both point along one line, so <span class="c-b">b</span> = [3; 1] is out of reach.
Canvas: s.A tweens to [[1,2],[2,4]] (t 0→0.5): on the left the two lines rotate until parallel (a red g.marker.cross appears between them at t 0.6); on the right a₁ and a₂ collapse onto one teal line (g.line through origin along [1;2], labeled "column space"), b = [3;1] stays off it, a dashed gray g.line drops from b to the teal line to show the gap. Label "no solution".
Math panel: `det A = 0`, `b ∉ column space`.
### 6. Infinitely many: coincident lines, b on the column line · 4 s · flags: (none)
Narration: Keep that flattened <b>A</b> but move <span class="c-b">b</span> onto the column line, to [2; 4]. Now the two rows describe the <i>same</i> line, and every point on it is a solution. On the column side, many recipes reach <span class="c-b">b</span>: 2a₁ + 0a₂, 0a₁ + 1a₂, and all between.
Canvas: b tweens to [2,4] (t 0→0.4): left — line 2 slides onto line 1, the merged line glows gold with label "every point solves it"; right — b sits on the teal line, three alternative tip-to-tail recipes play in sequence (t 0.4→1), each ending on b. A dashed gold g.line of solutions {x : Ax = b} = {[2;0] + t[−2;1]} appears on a small inset labeled "solution set".
Math panel: `x = [2;0] + t·[−2;1]` — the null-space direction [−2;1] in c-null.
### 7. Three planes in 3D · 5 s · flags: (none)
Narration: Three unknowns: each equation is now a flat <i>plane</i> in 3D. Two planes meet in a line; the third plane cuts that line at one point. Here x + y = 3, y + z = 5, x + z = 4 meet at [1; 2; 3].

Math panel: `[[1,1,0],[0,1,1],[1,0,1]] x = [3;5;4]`, `x = [1;2;3]` in gold.
### 8. Columns in 3D reach b · 4 s · flags: (none)
Narration: Same system, column view: the three columns <span class="c-i">[1;0;1]</span>, <span class="c-j">[1;1;0]</span>, <span class="c-k">[0;1;1]</span> are stacked with weights 1, 2, 3 and arrive exactly at <span class="c-b">b</span> = [3; 5; 4]. One picture is about where sheets cross; the other is about reaching a point. Same x.
Canvas: Planes fade out (t 0→0.2). g.vector columns in green/red/blue from origin; b orange. t 0.2→1 tip-to-tail chain: 1 green copy, 2 red copies, 3 blue copies, ending on b with a gold ring.
Math panel: `1·a₁ + 2·a₂ + 3·a₃ = b` colored by column.
### 9. Why ML cares: every "solve" is one of these · 4 s · flags: mlTie
Narration: Training a linear model means finding weights w with Xw ≈ y. With more data points than weights, the "lines" rarely all cross — the <i>no solution</i> case is the normal case in ML. Part 3 turns that into a question with a best answer: the shadow of y on the column space.

Math panel: `Xw ≈ y`, `(12×2)(2×1) ≈ (12×1)`.
### 10. Recap · 2.5 s · flags: recap
Narration: Rows: each equation is a line or plane; the solution is where they all meet. Columns: Ax = b asks for the recipe of columns that reaches <span class="c-b">b</span>. One answer, none, or a whole line of them — and the two pictures always agree.
Canvas: Three mini-cards: (1) two lines crossing at a gold dot; (2) two colored arrows tip-to-tail reaching an orange dot; (3) a parallel pair with a red ✕ beside a coincident pair with a gold dashed line.
Math panel: `Ax = b`.

## p3-02-elimination — Gaussian elimination, visually
**Part** 3 · **Tags** extension · **Dims** 2D · **Minutes** ~8 · **Prereqs** p3-01-systems-row-column, p2-04-composition
**Goal.** The learner sees that each row operation rotates one line about the fixed intersection point, so elimination never moves the answer, and that each operation is itself a matrix E multiplying both A and b.
**Badge.** drawnIn: 2D · realSize: solvers (LU) run elimination on 10⁴×10⁴ systems; `np.linalg.solve` is this · transfers: a row operation is always "replace one equation by itself plus a multiple of another"; the solution set never changes, in any size.
**Can't show.**
- Pivoting for numerical stability (swapping rows to avoid tiny pivots) — only its geometry (swap = relabel lines) is shown.
- Cost: elimination is ~n³/3 operations; the picture has no sense of cost.
**Terms.** row operation — add a multiple of one equation to another, scale an equation, or swap two; elimination matrix E — the matrix that performs one row operation when multiplied on the left; pivot — the entry used to clear the entries below it; back substitution — solving the triangular system from the bottom up.
**State.** `s.A` (2×2), `s.b`, `s.ops` (list of applied E matrices), `s.E` (current E being applied, tweened from I), `s.t` (progress of current op), `s.pivot` ([i,j] highlighted), `s.history` (A,b after each op for undo).
**Steps.**
### 1. Start: two lines, one crossing · 3 s · flags: (none)
Narration: Take x + 2y = 5 and 3x + 4y = 11. The row picture shows two lines crossing at the gold point [1; 2]. Elimination is a way to <i>find</i> that point without guessing — by tilting the lines until the answer can be read off.
Canvas: Row lines for A=[[1,2],[3,4]], b=[5;11]: line 1 through (5,0),(1,2); line 2 through (3,0.5),(1,2). Gold g.point at (1,2) (not labeled yet with coordinates — just "?").
Math panel: `[[1,2],[3,4]] [x;y] = [5;11]`.
### 2. One row operation: the line rotates about the answer · 4.5 s · flags: (none)
Narration: Replace row 2 by row 2 − 3·row 1. Watch: line 2 <i>rotates</i>, but about the gold point — because any point on both old lines satisfies the new equation too. The crossing cannot move. Row 2 is now 0x − 2y = −4.
Canvas: s.E tweens I → [[1,0],[−3,1]] (t 0→1); line 2 is re-drawn each frame from the current row (A' = E A, b' = E b), visibly pivoting about (1,2). A dashed ghost of the old line 2 stays. The entry a₂₁ in the panel counts 3 → 0 and turns dim; the pivot a₁₁ = 1 pulses gold.
Math panel: `E₁ = [[1,0],[−3,1]]`, `E₁A = [[1,2],[0,−2]]`, `E₁b = [5;−4]` (live, tweened).
### 3. The new line is horizontal: read y · 3 s · flags: (none)
Narration: 0x − 2y = −4 has no x in it, so its line is horizontal: y = 2. One coordinate of the answer is now visible by eye. That is the whole point of making an entry zero.
Canvas: Line 2 is now horizontal at y = 2, drawn gold; a g.dim marker from the x-axis up to the line labeled "y = 2". The gold point gets its label "[?; 2]".
Math panel: `−2y = −4 ⇒ y = 2`.
### 4. Second operation: make line 1 vertical · 4 s · flags: (none)
Narration: Now clear the 2 above the second pivot: row 1 ← row 1 + row 2. Line 1 rotates about the same gold point until it is vertical: x = 1. The system is diagonal; the answer is written on the axes.
Canvas: E₂ = [[1,1],[0,1]] tweens in; line 1 pivots about (1,2) to vertical x = 1 (gold). Both lines gold, axis-aligned; the gold point labeled "[1; 2]".
Math panel: `E₂E₁A = [[1,0],[0,−2]]`, `E₂E₁b = [1;−4]`; then `x = 1, y = 2`.
### 5. Scaling a row changes nothing you can see · 2.5 s · flags: (none)
Narration: Multiply row 2 by −½: the equation −2y = −4 becomes y = 2. The line does not even move — scaling an equation rescales its numbers, not its points. Now the matrix is the identity and <span class="c-b">b</span> has become the answer.
Canvas: Panel-only change; a brief gold flash on line 2 to show it was "touched" but did not move.
Math panel: `D = [[1,0],[0,−½]]`, `D E₂E₁ A = I`, `D E₂E₁ b = [1;2]`.
### 6. The operations are a matrix — the inverse, assembled · 4 s · flags: (none)
Narration: Every step was a left-multiplication. Chain them: (D E₂ E₁) A = I, so D E₂ E₁ is exactly <b>A⁻¹</b>. Elimination never computes the inverse first; it builds it as a side effect of tilting lines. Solvers stop at the triangular stage — cheaper.
Canvas: Three small matrix tiles E₁, E₂, D slide together (composition picture from p2-04) into one tile labeled A⁻¹ = [[−2,1],[1.5,−0.5]]; a grid-morph thumbnail of A then A⁻¹ returns to the ghost grid.
Math panel: `A⁻¹ = D E₂ E₁ = [[−2,1],[1.5,−0.5]]`, `A⁻¹A = I`.
### 7. Misconception: "row operations change the solution" · 3.5 s · flags: misconception
Narration: ✕ Someone adds 5 to only the <i>left</i> side of an equation. Now the line really does move, and the crossing jumps. A row operation acts on the whole row — <b>A</b> and <span class="c-b">b</span> together — or it is not a row operation.
Canvas: Replay step 2 but with E applied to A only (b unchanged): line 2 rotates about a different point; the old gold crossing is left behind as a ghost, a red g.marker.cross appears on the new crossing with label "wrong system". Then the correct version replays and the crossing stays put with a green g.marker.check.
Math panel: `E·A, b` (red ✕) vs `E·A, E·b` (green ✓).
### 8. Why ML cares: solve, don't invert · 3.5 s · flags: mlTie
Narration: `solve(A, b)` in every numerics library is elimination with row swaps. It is cheaper and more accurate than forming <b>A⁻¹</b> and multiplying. When you fit a linear regression by the normal equations (p3-06), the library eliminates — it never inverts.
Canvas: A 6×6 heatmap (g.heat2d) of a random symmetric positive-definite matrix is eliminated column by column (entries below the diagonal fade to the background one column per 0.4 s) until triangular; a counter "pivots: 6/6".
Math panel: `XᵀX w = Xᵀy` → `solve`.
### 9. Recap · 2.5 s · flags: recap
Narration: A row operation rotates one line about the common crossing, so the answer never moves. Zero entries make lines axis-aligned and the answer readable. Each operation is a matrix E; their product is <b>A⁻¹</b>, built on the way.
Canvas: Three mini-cards: (1) a line pivoting about a gold dot; (2) two gold axis-aligned lines; (3) E₂E₁A = I tiles.
Math panel: `E_k⋯E₁ A = I`.
**Playground.** controls: button · "row₂ ← row₂ − m·row₁" (m from slider) · "Eliminate"; slider · bind `m` · −4..4 step 0.5 · "multiplier m"; button · "swap rows" · "Swap"; button · "scale row 2 by c" (slider c) · "Scale"; button · "Undo"; button · "Auto-solve" (plays the full sequence). Presets: "Step-2 system" A=[[1,2],[3,4]], b=[5;11]; "Needs a swap" A=[[0,2],[3,1]], b=[4;5]; "Singular" A=[[1,2],[2,4]], b=[3;1] (elimination produces 0 = −5: a red ✕ and label "no solution"). Live: lines, pivots pulsing, E tile and current A, b.
**Checks.**
1. kind: manipulate · prompt: "Use row operations until one line is horizontal and one is vertical." · setup: A=[[1,2],[3,4]], b=[5;11] · judge: |a₁₂| < 0.05 and |a₂₁| < 0.05 (LA.TOL.scalar) · hint: "Clear the entry below the first pivot first, then the one above the second." · solution: apply E₁=[[1,0],[−3,1]] then E₂=[[1,1],[0,1]].
2. kind: entry · prompt: "Type the elimination matrix that zeroes the entry under the first pivot of [[2,1],[1,3]]." · setup: A=[[2,1],[1,3]] · judge: entry 2×2 within LA.TOL.entry (0.05) of [[1,0],[−0.5,1]] (picture: line 2 rotates live as the entry is typed) · hint: "Row 2 minus (1/2) of row 1." · solution: [[1,0],[−0.5,1]].
3. kind: manipulate · prompt: "In at most two operations, zero a₂₁ in the 'Needs a swap' system." · setup: A=[[0,2],[3,1]], b=[4;5] · judge: |a₂₁| < 0.05 and ops.length ≤ 2 · hint: "A zero pivot cannot clear anything — swap first." · solution: swap rows (a₂₁ becomes 0 immediately).
**ML tie-in.** Previews p3-06-regression-matrix-form: normal equations are solved, not inverted; previews p4-12 where tiny pivots (ill-conditioning) make elimination unreliable.
**Recap cards.** Pivot about the answer · Zeros = axis-aligned lines · E-chain = A⁻¹.

## p3-03-projections — Projection onto a line and a plane
**Part** 3 · **Tags** core · **Dims** both · **Minutes** ~10 · **Prereqs** p1-06-dot-product, p2-08-rank-column-null, p2-10-transpose-outer-symmetric
**Goal.** The learner can drop the shadow of a vector onto a line or a plane, write it as (a·w / a·a)a or A(AᵀA)⁻¹Aᵀb, and recognize a projection matrix by P² = P and rank < full.
**Badge.** drawnIn: 2D and 3D · realSize: least squares projects y ∈ ℝⁿ (n = number of training rows, often 10⁵) onto a d-dimensional column space · transfers: "residual ⟂ every spanning vector" is the complete definition in any dimension; the formula is unchanged.
**Can't show.**
- A plane inside ℝⁿ for n > 3; the residual is still a single perpendicular arrow, but we cannot draw the ambient space.
- Projection onto a 3-dimensional subspace of a 4-dimensional space (would need a 4th axis).
**Terms.** projection — the shadow of a vector on a line or plane, dropped perpendicularly; residual — what is left: the vector minus its shadow, perpendicular to the line/plane; projection matrix — the matrix P that computes the shadow, with P² = P; subspace — a flat set through the origin (line, plane, …) closed under adding and scaling; orthogonal — perpendicular, dot product zero.
**State.** `s.a` (line direction, yellow), `s.w` (vector to project, purple), `s.p` (projection, magenta, derived), `s.P` (projection matrix, derived), `s.view`, `s.cam`, `s.A` (3×2 for the plane), `s.b` (3-vector), `s.t` (tween for the drop), `s.showMatrixGrid` (bool), `s.applyTwice` (0,1,2).
**Steps.**
### 1. Recall: the shadow · 3 s · flags: (none)
Narration: From the dot product lesson: drop a perpendicular from <span class="c-w">w</span> = [1; 2] onto the line of <span class="c-v">a</span> = [3; 1]. Where it lands is the <b>projection</b> of w onto a — its shadow. Today we write that shadow as a vector and as a matrix.
Canvas: 2D grid; a yellow, w purple; a thin yellow g.line through origin along a (extent ±5). t 0→1: dashed gray g.line from w's tip drops perpendicularly to the line; magenta g.point lands at p = [1.5, 0.5] with g.label "p".
Math panel: `a = [3;1]`, `w = [1;2]`.
### 2. How far along a? The dot product says · 3.5 s · flags: (none)
Narration: The shadow lies on the line, so it is some multiple of <span class="c-v">a</span>: p = c·a. Its length along a is the dot product a·w = 5 divided by the length of a; dividing by |a| once more converts length to multiples of a: c = a·w / a·a = 5/10 = ½.
Canvas: g.dim from origin to p along the line labeled "a·w/|a| = 1.58"; then the yellow a is shown as a unit tick; the label morphs to "c = ½". The magenta p is drawn as a vector (g.vector origin→p) labeled "p = ½a".
Math panel: `c = (a·w)/(a·a) = 5/10 = 0.5`, `p = c·a = [1.5; 0.5]`.
### 3. The residual is perpendicular · 3.5 s · flags: (none)
Narration: What is left over, <span class="c-w">w</span> − <span class="c-mag">p</span> = [−0.5; 1.5], is the <b>residual</b>. It is exactly perpendicular to <span class="c-v">a</span>: (−0.5)(3) + (1.5)(1) = 0. That is not a coincidence — "perpendicular residual" is what <i>defines</i> the shadow.

### 4. Misconception: the shortest route is not the straight-down one · 3.5 s · flags: misconception
Narration: ✕ "The closest point on the line is straight below w." Dropping vertically lands at [1; 0.33], which is <i>farther</i> from w than p. Perpendicular to the line — not to the axis — is what minimizes the distance. Watch the two lengths.

### 5. The projection matrix: a rank-1 map · 4.5 s · flags: (none)
Narration: Projection is linear, so it has a matrix. From p = a(a·w)/(a·a) = (aaᵀ/aᵀa) w we read <b>P</b> = aaᵀ/aᵀa = [[0.9, 0.3],[0.3, 0.1]]. It is an outer product (p2-10), so its rank is 1: the whole plane is flattened onto the line.

Math panel: `P = aaᵀ/(aᵀa) = (1/10)[[9,3],[3,1]]`, columns colored.
### 6. Projecting twice changes nothing: P² = P · 3 s · flags: (none)
Narration: A shadow of a shadow is the same shadow. Apply <b>P</b> again and nothing moves: P² = P. Also det P = 0 — a projection cannot be undone, because every vector along the residual direction was crushed to zero.
Canvas: s.applyTwice: the already-flattened grid is hit by P once more — nothing moves; a green g.marker.check. The magenta null direction (perpendicular to a) is drawn as a line labeled "null space" (c-null) with vectors on it collapsing to the origin.
Math panel: `P² = P`, `det P = 0`, `rank P = 1`.
### 7. Onto a plane in 3D · 5 s · flags: (none)
Narration: Now the target is a plane: the span of <span class="c-i">a₁</span> = [1;0;1] and <span class="c-j">a₂</span> = [0;1;1]. <span class="c-b">b</span> = [1;2;6] sticks out of it. ### 8. Perpendicular to the whole plane means perpendicular to each column · 4 s · flags: (none)
Narration: The residual <span class="c-b">b</span> − <span class="c-mag">p</span> = [−1; −1; 1] must be perpendicular to <i>every</i> direction in the plane, and it is enough to check the two spanning vectors: (b − p)·a₁ = 0 and (b − p)·a₂ = 0. Two dot products, two equations, two unknown weights.

### 9. Written out: the normal equations · 4 s · flags: (none)
Narration: p = Ax̂ for some weights x̂ = [x₁; x₂]. "Aᵀ(b − Ax̂) = 0" rearranges to <b>AᵀA x̂ = Aᵀb</b> — the <b>normal equations</b>. Here AᵀA = [[2,1],[1,2]], Aᵀb = [7; 8], so x̂ = [2; 3] and p = 2a₁ + 3a₂ = [2; 3; 5].

### 10. Why ML cares: fitting is projecting · 3.5 s · flags: mlTie

### 11. Recap · 2.5 s · flags: recap

## p3-04-orthonormal-gram-schmidt — Orthonormal bases, orthogonal matrices, Gram–Schmidt, QR
**Part** 3 · **Tags** core · **Dims** both · **Minutes** ~11 · **Prereqs** p3-03-projections, p1-04-independence-basis, p2-03-transformation-zoo
**Goal.** The learner can read coordinates off an orthonormal basis with dot products, recognize an orthogonal matrix by "circles stay circles" and QᵀQ = I, and straighten any basis one vector at a time (Gram–Schmidt), recording what was removed as R in A = QR.
**Badge.** drawnIn: 2D and 3D · realSize: QR of a 10⁵×10³ design matrix is how `lstsq` is actually computed; orthogonal 4096×4096 matrices initialize transformer weights · transfers: QᵀQ = I, length preservation and "subtract the shadows, then normalize" are identical in every dimension; only the count of vectors grows.
**Can't show.**
- Reflections in n-D (det Q = −1) beyond a 3D mirror; we show one 2D reflection only.
- Loss of orthogonality from rounding in classical Gram–Schmidt (why libraries use Householder) — a numerical fact with no picture.
**Terms.** orthonormal — perpendicular to each other and each of length 1; orthogonal matrix — a square matrix whose columns are orthonormal, so QᵀQ = I and Q⁻¹ = Qᵀ; Gram–Schmidt — straighten a basis by subtracting each vector's shadows on the previous ones, then normalizing; QR decomposition — A = QR with Q orthonormal columns and R upper-triangular, the recipe for rebuilding A from Q.
**State.** `s.vs` (list of 2 or 3 input vectors), `s.qs` (orthonormal outputs, derived via LA.num.gramSchmidt steps), `s.stage` (which Gram–Schmidt sub-step is animating: 0..5), `s.t`, `s.Q`, `s.R`, `s.v` (test vector for coordinate readout, yellow), `s.theta` (rotation angle for the orthogonal-matrix demo), `s.view`, `s.cam`, `s.showCircle` (bool).
**Steps.**
### 1. A rotated grid is still a perfect grid · 3.5 s · flags: (none)
Narration: Rotate î and ĵ by 30°. The two arrows <span class="c-i">q₁</span>, <span class="c-j">q₂</span> are still perpendicular and still length 1: an <b>orthonormal basis</b>. Its grid is the ordinary grid, turned. Nothing is stretched, nothing is sheared.
Canvas: Grid morphs via s.theta 0→30° (tween the angle, build rot2 in render) over the ghost grid; q₁ green, q₂ red with unit ticks; the unit circle (g.circle) rides along and stays a circle.
Math panel: `Q = [[cos30°, −sin30°],[sin30°, cos30°]] = [[0.87,−0.5],[0.5,0.87]]`.
### 2. Coordinates by dot products · 4 s · flags: (none)
Narration: How much of <span class="c-v">v</span> = [2; 1] lies along <span class="c-i">q₁</span>? Its shadow — and since q₁ has length 1, the shadow length is just the dot product v·q₁ = 2.23. Same along q₂: v·q₂ = −0.13. In an orthonormal basis, coordinates are shadows.
Canvas: v yellow; dashed gray drops from v's tip onto the q₁ line and the q₂ line; the two shadow lengths labeled; the two numbers fly (ctx.fx.fly) into a bracket labeled "coordinates in Q".

### 3. Misconception: dot products do not read coordinates in a slanted basis · 3.5 s · flags: misconception
Narration: ✕ Try the same trick with the slanted basis <span class="c-v">a</span> = [3; 1], <span class="c-w">w</span> = [1; 2]: the shadows of v on a and on w, added tip-to-tail, miss v. Shadows only work when the basis vectors do not overlap — when they are perpendicular. That is why we want orthonormal bases.
Canvas: a yellow, w purple, v = [2;1] shown gray-white; shadows on a and w drawn as magenta points; the two shadow vectors added tip-to-tail end at a point visibly off v; red g.marker.cross there. Then the rotated q₁, q₂ redo it and land exactly (green check).

### 4. Orthogonal matrices keep lengths and angles · 4 s · flags: (none)
Narration: A matrix with orthonormal columns is an <b>orthogonal matrix</b>. It moves every vector without changing any length or angle: circles stay circles, squares stay squares. Compare a shear, which turns the circle into an ellipse. Rotations and reflections are the only 2D examples.
Canvas: Split: left, Q = rot(30°) acts on the unit circle and a square — circle stays a circle; right, S = [[1,1],[0,1]] turns the same circle into an ellipse (g.ellipse(S)). A reflection F = [[0,1],[1,0]] is then shown on the left with the fill turning violet (det −1) but the circle still a circle.
Math panel: `|Qv| = |v|`, `det Q = ±1`.
### 5. QᵀQ = I: four dot products · 3 s · flags: (none)
Narration: Why is Qᵀ the inverse of Q? The entries of QᵀQ are the dot products of the columns: q₁·q₁ = 1, q₁·q₂ = 0, q₂·q₁ = 0, q₂·q₂ = 1. The identity. Undoing a rotation costs a transpose, not an inversion.
Canvas: The 2×2 of QᵀQ fills cell by cell; as each fills, the corresponding pair of column arrows glows (same arrow twice for diagonal cells). The grid plays Q then Qᵀ and returns exactly to the ghost.
Math panel: `QᵀQ = [[q₁·q₁, q₁·q₂],[q₂·q₁, q₂·q₂]] = I`, `Q⁻¹ = Qᵀ`.
### 6. Gram–Schmidt, step 1: normalize the first · 2.5 s · flags: (none)
Narration: Take the slanted pair <span class="c-v">a</span> = [3; 1], <span class="c-w">w</span> = [1; 2] and straighten it. Step 1: keep a's direction, fix its length: q₁ = a/|a| = [0.95; 0.32].
Canvas: a shrinks along its own line to the unit circle (t 0→1); it is recolored green and relabeled q₁. |a| = 3.16 shown then fades.
Math panel: `q₁ = a/|a| = [0.95; 0.32]`, `r₁₁ = |a| = 3.16`.
### 7. Step 2: subtract the shadow, then normalize · 4.5 s · flags: (none)
Narration: Step 2: w's shadow on q₁ is (w·q₁)q₁ = 1.58·q₁. Lift it off: w − 1.58 q₁ = [−0.5; 1.5] is perpendicular to q₁ (it is the residual from p3-03). Normalize: q₂ = [−0.32; 0.95]. Two perpendicular unit vectors, built from two slanted ones.
Canvas: Magenta shadow of w on q₁ drawn; then the shadow arrow visibly slides out of w (t 0.2→0.6: the vector from the shadow tip to w translates to the origin), leaving the gray residual at the origin; it shrinks to unit length and turns red, labeled q₂. Right-angle marker between q₁ and q₂.
Math panel: `u₂ = w − (w·q₁)q₁ = [−0.5; 1.5]`, `q₂ = u₂/|u₂| = [−0.32; 0.95]`, `r₁₂ = w·q₁ = 1.58`, `r₂₂ = |u₂| = 1.58`.
### 8. R records what was removed: A = QR · 3.5 s · flags: (none)
Narration: Nothing was lost. a = 3.16 q₁ and w = 1.58 q₁ + 1.58 q₂. Put those recipes in columns: that is <b>R</b>, upper-triangular, and <b>A</b> = [a w] = <b>QR</b>. Q is the straightened frame; R is the recipe to rebuild the original from it.
Canvas: The gray original a, w reappear as ghosts; tip-to-tail along q₁, q₂ with the R weights rebuilds each (a: 3.16 q₁; w: 1.58 q₁ then 1.58 q₂) landing exactly on the ghosts with gold rings.
Math panel: `A = QR`, `Q = [[0.95,−0.32],[0.32,0.95]]`, `R = [[3.16,1.58],[0,1.58]]`.
### 9. Three vectors in 3D · 5 s · flags: (none)
Narration: In 3D the third vector has two shadows to lose — one on <span class="c-i">q₁</span>, one on <span class="c-j">q₂</span> — and what remains points straight out of their plane. Start from [1;1;0], [1;0;1], [0;1;1]: q₃ ends up along [−1; 1; 1]/√3, the normal of the first two.

Math panel: `q₃ = (v₃ − (v₃·q₁)q₁ − (v₃·q₂)q₂)/|…|`, `Q = [q₁ q₂ q₃]`, `QᵀQ = I₃`.
### 10. Why ML cares: safe matrices and the real least-squares solver · 3.5 s · flags: mlTie
Narration: Orthogonal matrices neither explode nor shrink anything, so deep networks are often <i>initialized</i> with them and recurrent weights kept near them. And `lstsq` fits a regression as X = QR, then solves Rw = Qᵀy — one shadow per column, no AᵀA, numerically safer. Rotating an embedding space (Q) changes no similarity.

### 11. Recap · 2.5 s · flags: recap
Narration: Orthonormal: perpendicular unit vectors, so coordinates are dot products and QᵀQ = I. Orthogonal matrices preserve lengths and angles — circles stay circles. Gram–Schmidt: subtract the shadows, normalize; R remembers what you removed, A = QR.
Canvas: Three mini-cards: (1) rotated grid with a circle; (2) a shadow lifting off w leaving a perpendicular remainder; (3) A = Q·R tiles.

## p3-05-least-squares — Least squares: fitting is projecting ★
**Part** 3 · **Tags** capstone · **Dims** both · **Minutes** ~13 · **Prereqs** p3-03-projections, p3-01-systems-row-column, p1-07-data-as-vectors
**Goal.** The learner can take three data points, flip them into one vector y ∈ ℝ³ whose axes are the data points, see every candidate line as a point on the plane spanned by the columns of X, and see the best fit as the perpendicular shadow of y on that plane — then read the normal equations off the picture.
**Badge.** drawnIn: 2D (data) + 3D (sample space, n = 3) · realSize: n = 10⁵ rows means y ∈ ℝ¹⁰⁰⁰⁰⁰ and a d-dimensional plane inside it · transfers: "residual ⟂ every column" and XᵀX ŵ = Xᵀy are exact for any n and d; only the ambient space becomes undrawable.
**Can't show.**
- Sample space for n > 3: with 12 points y lives in ℝ¹², which has no picture (we switch to a strip and keep the formula).
- Both spaces at once as one picture: feature space (axes = features) and sample space (axes = data points) are different rooms; the lesson walks between them.
- Statistical noise models (why squared error) — this lesson is geometry only.
**Terms.** least squares — choose the line that makes the sum of squared vertical errors smallest; residual — the vertical gap yᵢ − ŷᵢ between a data point and the line (and, as a vector, y − ŷ); sample space — the space whose axes are the data points, where the whole target column y is one arrow; design matrix X — one row per data point, one column per feature, plus a column of ones for the intercept; fitted values ŷ — the predictions Xw, a point on the column plane; normal equations — XᵀX ŵ = Xᵀy, "the residual is perpendicular to every column" written out.
**State.** `s.pts` (array of {x,y}; default [(1,1),(2,2),(3,2)]), `s.w` ([w₀,w₁] current line), `s.what` ([ŵ₀,ŵ₁] least-squares, derived via LA.num.lstsq), `s.yvec` (y as a vector), `s.yhat` (Xw), `s.e` (residual), `s.sse`, `s.view` ('2d'|'3d'|'split'), `s.cam`, `s.flyT` (progress of the bracket fly-in), `s.n` (3 or 12), `s.showSquares` (bool), `s.mode` ('vertical'|'perp' for the misconception), `s.r2`.
**Steps.**
### 1. Three points, one candidate line · 3.5 s · flags: interactive
Narration: Three measurements: (1, 1), (2, 2), (3, 2). We want a line y = w₀ + w₁x that comes closest to all three. Any line misses some points; the vertical gaps are the <b>residuals</b>. Try the sliders — watch the gaps and their squares.
Canvas: 2D axes (x 0..4, y 0..3). Three white g.points; a gold-dim candidate line for s.w = [0.5, 0.4]; dashed gray vertical residual segments from each point to the line; at each residual a small gray square of side |residual| (s.showSquares). Readout label "sum of squares = 0.63". Sliders live in this step.
Math panel: `ŷᵢ = w₀ + w₁xᵢ`, `SSE = Σ(yᵢ − ŷᵢ)² = 0.63` (live).
### 2. Misconception: closest is not "perpendicular to the line" · 3.5 s · flags: misconception
Narration: ✕ "Measure the error perpendicular to the line." The error of a prediction is in y — the thing we predict — so the gap is vertical. Perpendicular distances give a different, wrong line here (the gray one). Least squares always means vertical gaps, squared, summed.

### 3. The flip: three numbers become one arrow · 5 s · flags: (none)
Narration: Here is the move that makes everything geometric. Collect the three y-values — 1, 2, 2 — into one tall bracket. That bracket is a single vector <span class="c-b">y</span> in a 3D space whose axes are not features but <i>the data points themselves</i>: axis 1 is point 1, axis 2 is point 2, axis 3 is point 3.

A caption on the 3D side: "sample space: one axis per data point".
Math panel: `y = [1; 2; 2]` in c-b with row labels "pt 1, pt 2, pt 3".
### 4. The columns of X are two arrows in that same space · 4 s · flags: (none)
Narration: Write the line's ingredients the same way. The intercept adds w₀ to every point — a column of ones, <span class="c-i">[1;1;1]</span>. The slope adds w₁xᵢ — the column <span class="c-j">x = [1;2;3]</span>. Side by side they form the <b>design matrix X</b>: one row per point, one column per feature.

## p3-06-regression-matrix-form — Regression as X, w: normal equations, pseudo-inverse, min-norm
**Part** 3 · **Tags** core · **Dims** both · **Minutes** ~11 · **Prereqs** p3-05-least-squares, p2-09-non-square, p2-08-rank-column-null
**Goal.** The learner can build the design matrix for several features, read the fitted plane and residual sticks in feature space, write ŵ = X⁺y for a tall X, and see that a wide X has a whole line/plane of perfect fits of which the pseudo-inverse picks the one nearest the origin.
**Badge.** drawnIn: 2D and 3D (d = 2 features, n = 12 rows) · realSize: X is n×d with n = 10⁶, d = 10³ (tall) or a 10⁹-parameter network with 10⁶ examples (wide) · transfers: the shapes (n×d)(d×1) = n×1, the normal equations and the two pseudo-inverse formulas are size-independent.
**Can't show.**
- More than two features as a plane: with d = 3 the "plane" is a 3D flat inside 4D.
- Sample space for n = 12 (we stay in feature space here; p3-05 did the flip).
- Numerical behavior of (XᵀX)⁻¹ beyond a hint: κ and ridge come in p4-12.
**Terms.** design matrix X — rows are examples, columns are features, first column all ones for the intercept; feature space — the space whose axes are the features (plus one for y), where each example is a point; tall X — more rows than columns (n > d): usually no exact fit, use least squares; wide X — more columns than rows (n < d): infinitely many exact fits; pseudo-inverse X⁺ — the matrix giving the least-squares fit for tall X and the minimum-norm fit for wide X; minimum-norm solution — among all exact solutions, the one closest to the origin; ill-conditioned — small changes in the data cause large changes in the answer.

### 1. The table becomes X · 3.5 s · flags: (none)

Narration: ✕ "Drop the ones column; the slopes will adjust." Without it the plane is nailed to the origin — it must pass through (0, 0, 0) — and the sticks grow. The intercept is not a separate formula; it is just one more column of X, and it is the column that lets the plane float.

Narration: ✕ Add a third feature that is a copy of x₁. The plane fits exactly as before, but the weights are no longer unique: w₁ and w₃ can trade off freely, and XᵀX has det = 0. ## p3-07-gram-matrix — The Gram matrix: all pairwise dot products
**Part** 3 · **Tags** core · **Dims** 2D · **Minutes** ~9 · **Prereqs** p1-06-dot-product, p2-10-transpose-outer-symmetric, p3-06-regression-matrix-form
**Goal.** The learner can build K = XXᵀ from a cloud of points, read any cell as a dot product (length × length × cos θ), tell XXᵀ (n×n, pairs of points) from XᵀX (d×d, pairs of features), and know why every Gram matrix is symmetric and never negative on vᵀKv.
**Badge.** drawnIn: 2D (six points, d = 2) · realSize: attention computes a 4096×4096 Gram-like matrix per head; a kernel SVM on 10⁵ examples has a 10⁵×10⁵ K · transfers: K_ij = xᵢ·xⱼ is one number per pair in any d; symmetry and positive semi-definiteness hold for every size.
**Can't show.**
- Points in d > 3 — but K never needs them drawn: it is n×n whatever d is.
- Kernel feature spaces (infinite-dimensional); only their Gram matrix exists on screen (p6-05).
**Terms.** Gram matrix — the matrix of all pairwise dot products, K = XXᵀ with K_ij = xᵢ·xⱼ; positive semi-definite (PSD) — vᵀKv ≥ 0 for every v, i.e. K never flips a vector to point against itself; cosine matrix — the Gram matrix of the unit-normalized vectors, entries cos θᵢⱼ; XᵀX vs XXᵀ — pairs of features (d×d) vs pairs of examples (n×n).
**State.** `s.pts` (six 2D vectors: [2,0],[1.5,1.5],[0,2],[−1,1],[−2,−1],[1,−2]), `s.K` (6×6 derived), `s.G` (XᵀX 2×2 derived), `s.hot` ([i,j] hovered cell or null), `s.fillT` (how much of K has filled, 0..36), `s.normalize` (bool: cosine matrix), `s.v` (test vector for vᵀKv, 6-vector), `s.showFeatures` (bool).
**Steps.**
### 1. Six arrows, one number per pair · 3.5 s · flags: (none)
Narration: Six data points drawn as arrows from the origin. For any <i>pair</i>, the dot product is one number: how much they point the same way, times their lengths. x₁·x₂ = 2·1.5 + 0·1.5 = 3. Six arrows make 36 pairs. Let us collect all 36 numbers in one table.
Canvas: 2D grid; six gray-white g.vectors labeled x₁…x₆. x₁ and x₂ glow (yellow and purple tints), an angle g.arc between them, the dashed shadow of x₂ on x₁; "3" appears at the arc and flies toward an empty 6×6 grid on the right (g.heat2d with blank cells).
Math panel: `x₁·x₂ = 2·1.5 + 0·1.5 = 3`.
### 2. Filling K row by row · 5 s · flags: (none)
Narration: Row i, column j holds xᵢ·xⱼ. Row 1 is x₁ against everyone: 4, 3, 0, −2, −4, 2. The diagonal is each arrow against itself — its squared length. This 6×6 table is the <b>Gram matrix</b> K = XXᵀ: the whole cloud's geometry, with no coordinates in it.
Canvas: s.fillT 0→36: cells fill one by one (0.14 s each) in the diverging palette (blue negative, dark zero, orange positive, values printed); as each cell fills, the two arrows glow briefly. Diagonal cells get a thin gold border.
Math panel: `K = XXᵀ`, `K_ii = |xᵢ|²`, `(6×2)(2×6) = 6×6`.
### 3. Hover a cell: the angle is in the sign · 3.5 s · flags: interactive
Narration: Hover any cell. Positive: the two arrows lean the same way. Zero: perpendicular (x₁ and x₃). Negative: they lean apart (x₁ and x₅ point nearly opposite: −4). The table is a map of agreements and disagreements.

### 4. Misconception: a big number means similar · 3.5 s · flags: misconception
Narration: ✕ "K₂₅ = −4.5 is the biggest magnitude, so x₂ and x₅ are the most related." Length inflates dot products. Divide each entry by both lengths and you get the <b>cosine matrix</b>: every entry is between −1 and 1. Now x₂ and x₅ read −1.0: exactly opposite, not similar.

Math panel: `K̂ = D^{−1/2} K D^{−1/2}`, `K̂_ij = cos θ_ij`.
### 5. Symmetric, always · 2.5 s · flags: (none)
Narration: xᵢ·xⱼ = xⱼ·xᵢ, so K_ij = K_ji: the matrix is a mirror image of itself across the diagonal. Every Gram matrix is symmetric — which, as Part 4 shows, gives it perpendicular eigenvectors and real eigenvalues.
Canvas: s.normalize off. The upper triangle lifts and folds over the diagonal (entries slide across, p2-10 style) landing exactly on the lower triangle; a gold diagonal line.
Math panel: `K = Kᵀ`.
### 6. Two Gram matrices: pairs of points vs pairs of features · 4 s · flags: (none)
Narration: X is 6×2. XXᵀ pairs <i>points</i>: 6×6. Flip the order and XᵀX pairs <i>features</i>: 2×2 — the dot products of the two columns, 12.25 and 12.25 on the diagonal, 1.25 off it. Center the points and divide by n and that small one becomes the covariance matrix (p4-09). The normal equations used it too.

Math panel: `XXᵀ (n×n)`, `XᵀX (d×d) = [[12.25, 1.25],[1.25, 12.25]]`.
### 7. Never negative: vᵀKv = |Xᵀv|² · 4 s · flags: (none)
Narration: Take any six weights v and compute vᵀKv. It equals |Xᵀv|² — the squared length of the weighted sum of the six arrows — so it can never be below zero. That property is called <b>positive semi-definite</b>. K is also flat: six points in 2D give a 6×6 matrix of rank only 2.
Canvas: A random v (bars, 6 cells) changes every 0.8 s; the weighted sum Σvᵢxᵢ is drawn as a gray vector whose squared length is printed; a live bar "vᵀKv" never dips below 0 (axis marked). Readout "rank K = 2".
Math panel: `vᵀKv = vᵀXXᵀv = |Xᵀv|² ≥ 0`, `rank K ≤ d = 2`.
### 8. The picture stops at 3; K does not · 3 s · flags: (none)
Narration: Give each point 64 features instead of 2. We cannot draw the arrows, but K is still 6×6 with the same meaning: one dot product per pair. The picture stops at 3. The formula does not — a sum of products with more terms.

Math panel: `K_ij = Σ_{k=1}^{64} X_ik X_jk`.
### 9. Why ML cares: attention and kernels are Gram matrices · 3.5 s · flags: mlTie
Narration: Attention scores are QKᵀ: every query against every key — a Gram-style table of dot products, one row per token. Kernel methods replace xᵢ·xⱼ by k(xᵢ, xⱼ) and never look at the points again: the Gram matrix is <i>all</i> they need. Both lessons wait in Part 6.

Math panel: `scores = QKᵀ`, `K_ij = k(xᵢ, xⱼ)`.
