# Part 6 — Linear algebra inside ML models

**Through-line.** Everything from Parts 0–5 is now used, not taught. The learner first settles the bookkeeping that trips up every beginner reading ML code — the same array is both a table of points and a stack of rows multiplied by Wᵀ, and shapes must chain (p6-01). Then six capstones, each a complete ML component rebuilt from the course's own primitives: embeddings as arrows whose angles carry meaning (p6-02), attention as shadows → softmax → tip-to-tail sum (p6-03), a softmax classifier as arrows tiling the plane (p6-04), the kernel trick as a lift followed by a flat cut (p6-05), convolution as a banded matrix (p6-06, extension), LayerNorm/BatchNorm as projection and axis scaling (p6-07, extension). The grand capstone (p6-08) puts a boundary rotating in data space beside a GD path on loss contours with Hessian eigenvectors, and shows a hidden layer only as its labeled PCA shadow. Order is fixed: p6-01 → p6-02 → p6-03 → p6-04 → p6-05 → (p6-06, p6-07 off the recommended path) → p6-08. Softmax was taught in p4-04 and the neural layer in p2-12; both are referenced, never re-taught.

**Part-level conventions (in addition to STYLE.md).** Query q: yellow `c-v`; keys: teal `c-teal`; values: purple `c-w`; attention weights / scores / class arrows that win: gold `c-gold`; outputs: orange `c-b`. Tokens, words and data points use the data colors ("the blue points", "the rose points"; a third class, when needed, is "the orange points" using `b`). All data comes from the seeded generators named in each lesson's State; trained networks ship hard-coded weights produced by the deterministic procedure stated in the lesson, with an optional "Retrain" button; only p2-12's width-3 net trains at load. Every n > 3 step carries the exact line "The picture stops at 3. The formula does not."

## p6-01-batches-shapes-tensors — Batches, shapes, tensors, broadcasting; two faces of a matrix
**Part** 6 · **Tags** core · **Dims** both · **Minutes** ~10 · **Prereqs** p2-02-matrix-vector, p2-09-non-square, p2-10-transpose-outer-symmetric, p2-11-affine-bias, p1-07-data-as-vectors
**Goal.** The learner can look at the same array as 8 points or as 8 rows, write a batched layer as H = XWᵀ + 1bᵀ with shapes that chain, and read a 4-index tensor as stacked slices.
**Badge.** drawnIn: 2D data (d = 2) lifted to h ≤ 3 outputs in 3D · realSize: X is 60,000×784 for a digit set; a transformer activation tensor is (32, 2048, 4096) · transfers: XWᵀ row by row, broadcasting as the outer product 1bᵀ, matmul on the last axis only — exact at any size.
**Can't show.**
- The 784 feature columns of a real X; we draw 2.
- More than 3 output units per point.
- Batch × time × feature at once beyond three stacked 2D slices.
**Terms.** batch — several samples processed together as rows of one matrix; data matrix X — n rows (samples) × d columns (features); shape — the list of sizes along each axis, e.g. (n, d); broadcasting — adding a row vector to every row, the outer product 1bᵀ; tensor (in ML) — an array with more than two indices, e.g. (batch, height, width, channels); reduction — summing or averaging along one axis, which removes it; row-major flatten — reading an array row by row into one long strip.
**State.** `s.X` 8×2 (`LA.rng.gaussianCloud(601, 8, {mean:[0.5,0.2], cov:[[1,0.4],[0.4,0.6]]})`, rounded to 1 decimal); `s.W` 3×2 (default [[1, 0.5],[−0.5, 1],[0.8, −0.6]]) of which the first `s.h` rows are used; `s.h` 1–3; `s.b` [3] bias (default [0.4, −0.2, 0.3]); `s.useBias`; `s.n` 2–12 (first n rows of a 12-row cloud); `s.hiRow` highlighted row index; `s.img` 6×6×3 (`LA.rng.smallImage(602, 6, 6, 3)`); `s.tiles` shape-tile puzzle state (check 1); `s.guessW` 2×2 typed (check 2); `s.view`, `s.cam`. Layout: table/heatmaps in the left 40% of world space (`g.heat2d` with printed values), the plane/3D scene on the right.

### 4. All samples at once: H = XWᵀ · 4 s · flags: (none)
Narration: Lie every sample down as a row and multiply on the right by Wᵀ: H = XWᵀ, shapes (8×2)(2×2) → (8×2). Each output row is one sample's result. One multiplication moves all eight points. This is why code writes <b>x @ W.T</b>.

Math panel: H = X Wᵀ · (n×d)(d×h) → (n×h)
### 5. Why the transpose · 3 s · flags: (none)
Narration: From p2-10: (Wx)ᵀ = xᵀWᵀ. Standing up, a sample is multiplied by W; lying down, by Wᵀ. The transpose flips the recipe so that rows stay rows. Nothing about the layer changed — only the orientation of the bookkeeping.
Canvas: W's entries slide across the diagonal into Wᵀ (0→0.5); the row xᵀ slides over the columns of Wᵀ (0.5→1), each dot product lighting one output cell (p2-02 row view).
Math panel: (W<span class="c-v">x</span>)ᵀ = <span class="c-v">x</span>ᵀWᵀ
### 6. Changing width · 4 s · flags: (none)
Narration: Give W three rows: now H = XWᵀ is 8×3 and every point gets a third coordinate. The eight points lift into 3D onto a tilted plane (p2-09): a layer that changes width changes dimension, for the whole batch at once.
Canvas: `s.h` 2 → 3; `s.view='3d'` eases in; the 8 points lift along dashed vertical sticks to their 3D positions; the teal plane (column space of Wᵀ) they lie on; shape tiles (8×2)(2×3) → (8×3); camera orbits yaw 20°→60°.
Math panel: W ∈ ℝ³ˣ² · H = XWᵀ ∈ ℝ⁸ˣ³
### 7. Bias is broadcast · 4 s · flags: (none)
Narration: Add the bias <span class="c-b">b</span> to every row: the whole cloud slides by b (p2-11). Code writes "+ b" once; the array behind it is 1bᵀ — a column of ones times the row bᵀ, the outer product from p2-10. Broadcasting is an outer product you never see.
Canvas: left: the 1×3 row b stacks into 8 ghost copies forming the 8×3 matrix 1bᵀ (0→0.5), added to H; right: all 8 points translate by b in 3D (0.5→1) with the orange b arrow drawn once at the origin.
Math panel: H = XWᵀ + 1<span class="c-b">b</span>ᵀ
### 8. ✕ Shapes that do not chain · 3 s · flags: misconception
Narration: "Any two matrices can be multiplied." Try X(8×2) times W(3×2): the inner sizes 2 and 3 do not meet, and the tiles bounce apart. Transpose W and the 2s touch. Shape errors are the most common bug in ML code; this picture is the fix.

Math panel: (8×2)(3×2) ✕ · (8×2)(2×3) ✓
### 9. Tensors: more indices, stacked slices · 4 s · flags: (none)
Narration: An image is 6×6 pixels × 3 colors: three stacked 6×6 slices. Four images make a (4, 6, 6, 3) <b>tensor</b> — in ML the word just means "array with more indices". ### 10. Reductions: summing an axis away · 3 s · flags: (none)
Narration: Average down the rows (axis 0) and the 8×2 table becomes one 1×2 row: the mean point, the centroid from p4-09. Sum across each row (axis 1) and you get one number per sample. Reducing an axis removes it from the shape.
Canvas: left: the 8 rows of X slide down and merge into one row (0→0.5), the mean point appears in the plane (gold) ; then the columns merge sideways into an 8×1 strip (0.5→1); shape tags (8,2) → (1,2) and (8,2) → (8,1).
Math panel: mean(X, axis 0) ∈ ℝ¹ˣ² · sum(X, axis 1) ∈ ℝ⁸ˣ¹
### 11. Why ML cares: reading the shapes in code · 4 s · flags: mlTie
Narration: A digit batch is (32, 784); the layer weight is (128, 784); "x @ W.T" gives (32, 128). A transformer activation (32, 2048, 4096) times Wᵀ (4096, 1024) gives (32, 2048, 1024): only the last axis multiplies; the others ride along like our 8 rows. Attention (p6-03) is three of these.

Math panel: (B, T, d)·(d×h) → (B, T, h)
### 12. Recap · 2 s · flags: recap
Narration: A matrix has two faces: a table of samples or a map that moves them. A batch is rows times Wᵀ — one multiplication for everyone — and shapes must chain (n×d)(d×h). Bias is broadcast as 1bᵀ; tensors are stacked slices; reducing an axis removes it.

## p6-02-embeddings-analogies — Embeddings, analogies, cosine in 1000 dimensions
**Part** 6 · **Tags** capstone · **Dims** both · **Minutes** ~12 · **Prereqs** p1-06-dot-product, p1-08-high-dimensions-measured, p1-02-add-scale, p4-01-change-of-basis, p3-04-orthonormal-gram-schmidt
**Goal.** The learner can read meaning as direction, complete an analogy by vector arithmetic, see that rotating the whole space changes nothing, and knows why cosine beats distance in 1000 dimensions.
**Badge.** drawnIn: 3D authored toy with 10 words · realSize: word2vec is 300-D; GPT token embeddings are 4096–12288-D over 50k–200k tokens · transfers: cosine, difference vectors, rotation invariance and nearest neighbors are the same formulas in any d; the three named axes are a fiction — real axes have no names.
**Can't show.**
- 300–4096 axes; only the computed cosine histograms speak for them.
- Polysemy (one word, several meanings) and context-dependent embeddings.
- How embeddings are learned (p6-08 shows training for a classifier).
**Terms.** embedding — a vector assigned to a word or token; cosine similarity — the dot product of the two unit vectors, the cosine of their angle (p1-06); nearest neighbor — the word whose vector has the largest cosine with a query; analogy — "a is to b as c is to d", read as b − a ≈ d − c; displacement vector — the difference between two word vectors; rotation invariance — all cosines and differences survive when every vector is rotated by the same orthogonal matrix.
**State.** `s.words` 10 labeled 3D vectors from `LA.rng.wordVectors()`: authored values man (−0.5, 0, 0), woman (0.5, 0, 0), king (−0.5, 1, 0), queen (0.5, 1, 0), boy (−0.5, −0.7, 0), girl (0.5, −0.7, 0), france (0, −0.2, 1.2), paris (0, 0.3, 1.5), italy (0.4, −0.2, 1.3), rome (0.4, 0.3, 1.6), each plus N(0, 0.08²) noise from seed 602 (so king − man + woman lands within ~12° of queen, not on it); `s.analogy` preset index (king−man+woman, paris−france+italy, boy−man+woman → girl); `s.probe` [3] the analogy result or a dragged probe; `s.R` current rotation (identity or axis (1,1,1)/√3, 70°); `s.metric` ('cos'|'euclid'); `s.shadow` boolean (2D projection); `s.d` for the histogram (3, 10, 100, 1000); `s.hist` from `LA.rng.cosineHistogram(602, d)` (2000 pairwise cosines of random unit vectors); `s.docs` from `LA.rng.tokenVectors(603, 200, d)` with 5 planted clusters for the retrieval step; `s.selected` word index; `s.view`, `s.cam` (3D default yaw 35°, pitch 25°, auto-orbit 4°/s when idle).
**Steps.**

Narration: Ten words, each given a 3D vector by hand so we can see it: a gender axis, a royalty axis, a place axis. A model learns such vectors from text with no names on the axes; here we named them so you can check the geometry.

### 2. Similar meaning, similar direction · 3 s · flags: (none)

### 3. Nearest neighbors · 3 s · flags: (none)

### 5. A direction that means something · 3 s · flags: (none)

### 10. Real embeddings are strips · 4 s · flags: (none)
Narration: A real embedding is 300 to 4096 numbers — a strip, not an arrow. In high dimensions random directions are almost all perpendicular (p1-08): the cosine histograms narrow around 0 as d grows. The picture stops at 3. The formula does not.

Narration: 200 documents as random 64-D vectors with five planted topics, one query: the top-5 by cosine are the query's topic every time. Raise d: distances all become similar (nearest/farthest ratio → 1) while the cosine ranking stays sharp. That is why vector search uses dot products.

### 12. Recap · 2 s · flags: recap
Narration: Meaning is direction: similarity is cosine, relations are displacement arrows, analogies are parallelograms. Rotating the whole space changes nothing, and a 2D plot is only a shadow. In 1000 dimensions almost everything is perpendicular — room for thousands of meanings.
Canvas: three mini-cards: (1) king/queen arc; (2) the parallelogram walk; (3) the d = 1000 histogram spike.
Math panel: —

## p6-03-attention — Attention as dot products, softmax, weighted sum

## p6-05-kernel-trick — The kernel trick lifts 2D into 3D
**Part** 6 · **Tags** capstone · **Dims** both · **Minutes** ~12 · **Prereqs** p2-12-neural-layer, p1-09-first-model-neuron, p3-07-gram-matrix, p2-09-non-square, p6-04-softmax-classifier, p1-03-linear-combinations-span
**Goal.** The learner can lift the concentric circles onto a paraboloid, cut them with a plane, read the plane's cut back as a circle in 2D, and compute a lifted dot product without lifting.
**Badge.** drawnIn: 2D → 3D exact lift φ(x, y) = (x, y, x² + y²) · realSize: the RBF kernel's feature space is infinite-dimensional; an SVM on 10⁴ points uses a 10⁴×10⁴ Gram matrix · transfers: lift + flat cut = curved boundary; K = ΦΦᵀ; f(x) = Σ αᵢ k(xᵢ, x) + b — exact for any lift.
**Can't show.**
- The infinite-dimensional RBF feature space; only its Gram heatmap.
- Degree-2 polynomial lifts in 2D already have 6 features; we draw the 3-feature version.

## p6-06-convolution-matrix — Convolution is a matrix multiplication
**Part** 6 · **Tags** capstone, extension · **Dims** 2D · **Minutes** ~10 · **Prereqs** p2-02-matrix-vector, p6-01-batches-shapes-tensors, p5-06-chain-rule-backprop, p2-10-transpose-outer-symmetric
**Goal.** The learner can write a sliding 3-tap filter as a banded 6×8 matrix, read stride, padding and weight sharing off that matrix, and see a 3×3 image kernel as a 9×25 matrix.
**Badge.** drawnIn: 2D (signals, matrices, a 5×5 image) · realSize: a ResNet 3×3 conv 64→128 has 73,728 shared weights acting as a ~6·10⁶ × 3·10⁶ matrix that is never formed · transfers: banded + shared structure, y = Cx, Cᵀ for the backward pass, parameter count independent of input size — exact at any size.
**Can't show.**
- Multi-channel stacks beyond three slices.
- The full 10⁶×10⁶ matrix of a real layer (only its structure).
- The Fourier view of convolution.
**Terms.** filter / kernel taps — the short list of weights slid along the input; (cross-)correlation convention — output i = Σ_k f_k x_{i+k}, the way ML frameworks compute "convolution"; banded (Toeplitz) matrix — a matrix whose entries depend only on the diagonal they sit on; weight sharing — the same tap value repeated along a diagonal; stride — how many positions the filter jumps, which drops rows of C; padding — zeros added at the ends so the output keeps the input's length; transposed convolution — multiplication by Cᵀ, which spreads each output back over its inputs.
**State.** `s.x` [0, 0, 1, 1, 1, 0, 0, 2] (an edge up, an edge down, a spike); `s.f` taps (default [1, 0, −1]); `s.pos` sliding position 0–5 (tweened); `s.C` derived (out×8) from f, stride, padding; `s.stride` 1|2; `s.pad` boolean ('same' zero padding); `s.untied` boolean (independent entries, seeded `LA.rng(607)` perturbations); `s.img` 5×5 image (ones in rows/cols 1–3, zeros elsewhere); `s.K` 3×3 Sobel-x [[1, 0, −1],[2, 0, −2],[1, 0, −1]]; `s.C2d` derived 9×25; `s.clickCell` [row, col]; `s.view='2d'`. Default output y = Cx = [−1, −1, 0, 1, 1, −2].
**Steps.**
### 1. A filter slides · 4 s · flags: (none)
Narration: Eight samples: flat, a step up, a step down, a spike. Slide the three-tap filter f = [1, 0, −1] along them. At each position the output is the dot product (p1-06) of the window with the taps: x_i − x_{i+2}. Edges light up, flat parts give zero.
Canvas: `g.bars` of x (8 bars, top); a highlighted window of width 3 slides `s.pos` 0 → 5 over t; the taps drawn under the window; `g.bars` of y (6 bars, bottom) filling one at a time: −1, −1, 0, 1, 1, −2.
Math panel: yᵢ = Σₖ fₖ x_{i+k} = x_i − x_{i+2}
### 2. The same thing as a matrix · 4 s · flags: (none)
Narration: Each output is a row of numbers dotted with the whole input: the taps sitting at a shifted position, zeros elsewhere. Stack the six rows and you have a 6×8 matrix C with the filter marching down a diagonal band. The slide <i>is</i> y = Cx.
Canvas: a 6×8 `g.heat2d` (values printed, diverging palette) fills row by row in sync with the replayed slide; shape tiles (6×8)(8×1) → (6×1) snap; the band highlighted.
Math panel: y = Cx · C ∈ ℝ⁶ˣ⁸
### 3. Row view · 3 s · flags: (none)
Narration: Read it with p2-02's row view: y₃ is row 3 of C dotted with x. Row 3 is the filter parked at position 3. One matrix–vector product computes every window at once — the batch idea of p6-01, along the signal instead of across samples.
Canvas: row 3 of C underlined; the matching window of x highlighted; a magenta shadow-bar showing the dot product landing in y₃ = 1.
Math panel: y₃ = C₃,· · x
### 4. Shared weights on the diagonals · 3 s · flags: (none)
Narration: Look along the diagonals: every cell on the first band is 1, every cell on the third is −1, and everything off the band is 0. Three numbers describe eighteen nonzero cells. Local (zeros far from the band) and shared (same number along a diagonal) — that is a convolution.
Canvas: the cells of each diagonal pulse together in sequence (band 1, then 2, then 3); counter "3 parameters, 18 nonzero cells, 48 cells".
Math panel: C_{i, i+k} = f_k
### 5. Change the taps, keep the structure · 3 s · flags: (none)
Narration: Swap in a blur, f = [1, 2, 1]/4. The band stays; its numbers change; the output smooths instead of detecting edges. The matrix shape — where the zeros are — comes from sliding; the numbers come from the taps.
Canvas: `s.f` tweens to [0.25, 0.5, 0.25]; the heatmap's band recolors; the output bars morph to [0.25, 0.75, 1, 0.75, 0.25, 0.5]; the x bars unchanged.
Math panel: f = [¼, ½, ¼] · y live
### 6. ✕ Convolution is a special operation outside linear algebra · 4 s · flags: misconception
Narration: It is a matrix, so everything applies: rank, transpose, gradients as outer products (p5-06). Untie the weights and each band cell becomes free: the matrix is still 6×8 but now dense, with 48 parameters instead of 3. A fully connected layer is a convolution that forgot to share.

Math panel: tied: 3 parameters · untied: 6·8 = 48
### 7. The transpose runs it backward · 4 s · flags: (none)
Narration: Backprop (p5-06) pulls gradients through Cᵀ, an 8×6 matrix: each output cell spreads back to the three inputs it came from. Frameworks call this a transposed convolution and use it for upsampling. Nothing new: p2-10's transpose.

### 8. Stride and padding · 4 s · flags: (none)
Narration: Stride 2 keeps every other window: rows 2, 4, 6 of C vanish and the output halves. Padding adds zeros at both ends of x: two new columns, and C grows to 8×8 so the output keeps the input's length. Both are edits to the matrix.

Math panel: stride 2: C ∈ ℝ³ˣ⁸ · 'same' padding: C ∈ ℝ⁸ˣ⁸
### 9. A 2D image is a long vector · 5 s · flags: (none)
Narration: A 5×5 image flattened row by row (p1-07) is a 25-vector. A 3×3 kernel sliding over it becomes a 9×25 matrix: three bands, each a copy of a kernel row, shifted by a whole image row. The 9 outputs reshape into a 3×3 edge map.

### 10. Why ML cares: few weights, huge matrix · 4 s · flags: mlTie
Narration: A 3×3 conv from 64 to 128 channels has 73,728 weights, yet on a 224×224 image it acts as a matrix with millions of rows and columns that no one ever forms. Its gradient is a sum of outer products over every window position (p5-06). The picture stops at 3. The formula does not.

### 11. Recap · 2 s · flags: recap
Narration: A convolution is a matrix with two constraints: zeros away from a band (local) and equal numbers along each diagonal (shared). Stride drops rows, padding adds columns, the transpose runs it backward, and an image kernel is the same band pattern, one row per image row.

## p6-07-normalization-layers — LayerNorm and BatchNorm as geometry
**Part** 6 · **Tags** capstone, extension · **Dims** 3D · **Minutes** ~10 · **Prereqs** p3-03-projections, p4-09-covariance, p1-05-norms-distance, p4-11-whitening-mahalanobis, p5-03-gradient-descent

**Terms.** LayerNorm — per vector: subtract its own mean, divide by its own spread, then scale by γ and shift by β; BatchNorm — per feature: subtract the batch mean and divide by the batch spread; the all-ones direction 1 = (1,1,1) — along which a vector's mean lives; centering plane — the plane ⟂ 1 through the origin, where mean-zero vectors live; γ, β — learned per-feature scale and shift; batch statistics — means and spreads computed across the samples.

**Steps.**
### 1. Why normalize · 3 s · flags: (none)

Narration: The spread of the three entries is σ = ‖u‖/√3. Dividing by it scales u to length √3 (p1-05, normalizing): the tip lands on a circle of radius √3 drawn in the plane. Two numbers are gone — the vector's level and its scale. Its direction within the plane remains.

### 5. Every vector lands on the same circle · 4 s · flags: (none)

Narration: Finally the layer's own learned numbers: multiply each feature by γⱼ and add βⱼ. The circle becomes an ellipse (axis scales) and slides off the plane (a shift). The network can undo the normalization where it needs to, but starts from a clean circle.

### 10. Batch size matters · 3 s · flags: (none)
Narration: BatchNorm's means and spreads come from the batch. With four samples they are noisy: redraw the batch and the normalized cloud jumps. With forty it is steady. LayerNorm has no such dependence — one reason transformers use it.

## p6-08-watch-a-classifier-learn — Grand capstone: watch a classifier learn
**Part** 6 · **Tags** capstone · **Dims** both · **Minutes** ~15 · **Prereqs** p5-03-gradient-descent, p5-06-chain-rule-backprop, p6-04-softmax-classifier, p4-10-pca, p2-12-neural-layer, p1-09-first-model-neuron, p4-09-covariance
**Goal.** The learner can watch a boundary turn in data space while the same motion is a point sliding down a loss bowl in weight space, read the Hessian's eigenvectors off the data's spread, and see a hidden layer honestly as a labeled PCA shadow.
**Badge.** drawnIn: 2D data space + 2D weight space (bias fixed at 0) + 3D PCA shadow of ℝ⁴ · realSize: a modern model has 10⁹–10¹² weights and the same step rule w ← w − η∇L · transfers: boundary ↔ point duality, loss bowl from the data, H ≈ weighted covariance, the GD step, PCA shadows — exact in any n; only the bowl's dimension grows.
**Can't show.**
- Weight spaces with more than two parameters (we fix the bias at 0 so the bowl is drawable).
- The 17-dimensional non-convex loss of the small network — no contours are drawn for it.
- Mini-batch noise; the hidden layer in ℝ⁴ itself (shadow only, variance labeled).
**Terms.** data space — the plane of inputs where points and the boundary live; weight space — the plane of (w₁, w₂) where one model is one point; log-loss / cross-entropy — −[y log p + (1 − y) log(1 − p)] averaged over points; training trajectory — the sequence of weight points visited by gradient descent; hidden representation — the vector h a network computes for each input before the readout; PCA shadow — the projection of those vectors onto their top principal directions (p4-10), labeled with the variance kept.
**State.** `s.data` 80 points, 2 classes, `LA.rng.blobs(608, 2, 40, {centers:[[1.2,0.8],[−1.0,−0.6]], spread:0.7})`, then centered (so b = 0 is reasonable; stated on screen); `s.std` boolean (standardize features to unit spread); `s.w` [w₁, w₂] current logistic weights (start (−1.5, 2.0)); `s.eta` 1.5; `s.steps` 30; `s.path` precomputed GD trajectory on L(w) = mean log-loss + (λ/2)‖w‖², λ = 0.01; `s.loss` cached `g.contours` of L over w ∈ [−3,3]² (res 60, levels at 8 quantiles of L); `s.H` Hessian at the minimum, H = (1/n)Σ pᵢ(1 − pᵢ)xᵢxᵢᵀ + λI, its eigenvectors (gold) and λmax (red line at 2/λmax); `s.wstar` minimizer (Newton, 20 iterations in setup); `s.net` width-4 tanh network for moons: `LA.rng.moons(609, 60, 60, {noise:0.1})`, weights W₁ (4×2), b₁ (4), w₂ (4), b₂ hard-coded, produced by the deterministic procedure below, with snapshots at steps {0, 100, 300, 1000, 2000}; `s.snap` snapshot index; `s.hidden` 120×4 hidden vectors; `s.pca` top-3 PCs of the centered hidden vectors (`LA.num.pca`) and variance fraction; `s.clickPt` index for check 3; `s.view`, `s.cam`.
Deterministic training procedure for the net (run once by the implementer, paste constants, keep a "Retrain" button that reruns it in ≤ 150 ms): init from `LA.rng(609)` uniform(−0.5, 0.5); full-batch GD on mean log-loss, η = 0.5, 2000 steps, no momentum; round weights to 4 decimals; selftest asserts training accuracy ≥ 0.97 and that Retrain reproduces the constants within 1e-6.
**Steps.**
### 1. The data and the model · 3 s · flags: (none)
Narration: Eighty points, two classes, centered (p1-07). The model is p1-09's neuron with the bias fixed at zero so we can draw its weight space: p = σ(<span class="c-w">w</span>·x). Math panel: p = σ(<span class="c-w">w</span>·x) · b = 0 (fixed) · accuracy 0.49
### 2. Two spaces: a line here is a point there · 4 s · flags: interactive
